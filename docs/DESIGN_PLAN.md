# 프론트엔드 디자인 개편 계획

> 레퍼런스: Glossar 랜딩 페이지. **색감과 카드 디자인 요소만** 가져온다.
> 배경 이미지(수채화 풍경)는 쓰지 않는다. 배경은 무지(단색)다.
> 이 문서는 작업 지시서다. 한 번에 한 단계만 진행하고, 끝나면 체크하고 보고한 뒤 멈춘다.
> 시작할 때: `docs/DESIGN_PLAN.md의 D1을 진행해줘`

## 1. 가져올 것과 가져오지 않을 것

**가져온다**

| 레퍼런스 요소 | 특징 | 배우 DB에 적용 |
|---|---|---|
| 색감 | 흰색, 아주 옅은 회색(`#F5F5F7`), 검정. 채도 있는 색은 거의 없다 | 2장의 팔레트. 포인트 색은 `#F5F5F7` |
| 흰 카드 | 큰 라운드(24~28px), 테두리 없이 아주 옅은 그림자 | 화면의 큰 구역 (목록 영역, 상세 프로필, 폼, 표) |
| 카드 안의 회색 패널 | 흰 카드 안에 `#F5F5F7` 둥근 구역을 한 번 더 둔다 | 툴바, 필터, 탭 내용, 파일 업로드 영역 |
| 검정 알약 버튼 + 안쪽 배지 | "Download for iOS [$2.99]"처럼 버튼 안에 보조 정보 | 주요 버튼: "통합 PDF [12명]", "출결 저장 [8명]" |
| 검정 둥근 위젯 카드 | 어두운 카드, 왼쪽 위 작은 원형 배지("A1"), 큰 글자 | 강조 정보 카드: 키오스크 결과, 상세 화면 요약 통계 |
| 두 톤 문장 | 강조할 부분만 검정, 나머지는 회색 | 배우 요약 문장, 화면 부제 |
| 큰 숫자 통계 | "3,800+ words." 처럼 짧고 큰 글자 | 상세의 수업일지 수, 출석률 / 출결 화면의 출석 인원 |

**가져오지 않는다**: 수채화 풍경 배경, 배경 위에 떠 있는 시트 구조, 검정 알약 내비게이션, 청록색 행동 띠, 랜딩 페이지 수준의 큰 여백.
화면 배치(상단바, 목록, 상세, 폼의 위치)는 지금 구조를 유지하고, **색과 카드 모양만 바꾼다.** 목록, 출결, 관리자 표는 지금 정도의 밀도를 유지한다.

## 2. 색 팔레트와 토큰

`frontend/src/shared/styles/tokens.css`에 CSS 변수로 정의하고, 색, 간격, 라운드는 이 변수만 쓴다.
레퍼런스 색감 안에서만 고른다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--point` | `#F5F5F7` | **포인트 색.** 페이지 배경(무지), 카드 안 패널, 칩, 선택된 탭 배경, 표 머리글 |
| `--surface` | `#FFFFFF` | 카드 |
| `--surface-dark` | `#1D1D1F` | 검정 위젯 카드, 검정 알약 버튼, 활성 세그먼트 |
| `--ink` | `#1D1D1F` | 제목, 본문 |
| `--ink-2` | `#6E6E73` | 보조 텍스트 (`#F5F5F7` 위에서도 대비 약 4.6:1) |
| `--ink-3` | `#AEAEB2` | 플레이스홀더, 비활성 (흰 배경에서만, 본문에는 쓰지 않는다) |
| `--ink-on-dark` | `#FFFFFF` / `rgba(255,255,255,.6)` | 검정 카드·버튼 위 글자 / 보조 글자 |
| `--line` | `#E5E5EA` | 입력칸 테두리, 표 구분선 |
| `--danger` | `#D93A3A` | 삭제, 에러 (아주 적게 쓴다) |
| `--status-on` | `#1F8A4C` (글자) | 활동중, 출석. 배경은 `--point` 그대로 두고 글자색과 점(●)으로만 구분 |
| `--status-off` | `#6E6E73` (글자) | 계약만료, 미체크 |

| 분류 | 토큰 | 값 |
|---|---|---|
| 라운드 | `--r-card` / `--r-panel` / `--r-widget` / `--r-control` / `--r-pill` | 28 / 20 / 22 / 12 / 999px |
| 간격 | `--s-1` … `--s-8` | 4, 8, 12, 16, 24, 32, 48, 64px |
| 그림자 | `--shadow-card` | `0 1px 2px rgba(0,0,0,.04), 0 8px 24px rgba(0,0,0,.04)` (거의 안 보일 정도) |
| 글꼴 | `--font` | Pretendard, -apple-system, sans-serif |
| 글자 크기 | display / title / body / small | 32 / 22 / 15 / 13px. 제목은 700, 자간 -0.02em |

**색 사용 원칙**
- 화면 대부분은 흰색 + `#F5F5F7` + 검정 세 가지로 끝낸다.
- 주요 행동은 검정 알약 버튼(`--surface-dark`), 보조 행동은 `#F5F5F7` 알약 버튼.
- 상태는 색 배경 배지 대신 **점(●) + 글자색**으로 표시한다. 채도 있는 색은 상태 점과 에러에만 쓴다.
- `#F5F5F7`은 흰색과의 대비가 거의 없으므로(약 1.1:1) **글자나 테두리 색으로는 쓰지 않는다.** 면(배경)으로만 쓴다.

## 4. 구현 방식

- **CSS Modules** (Vite 기본 지원, 새 라이브러리 없음). 컴포넌트 옆에 `Card.module.css`처럼 둬서 코로케이션 구조와 맞춘다.
- 전역 CSS는 `tokens.css`(변수)와 `base.css`(reset, 글꼴, 무지 배경)만 남긴다. 2,152줄짜리 `style.css`는 화면을 옮길 때마다 해당 부분을 지우고 마지막에 삭제한다.
- TSX의 인라인 스타일(현재 85곳)은 모두 클래스로 옮긴다.
- 화면을 바꿀 때 E2E 셀렉터(`.card`, `.tab-btn`, `.kiosk-key`, 라벨 텍스트)가 바뀌면 `frontend/e2e/smoke.mjs`도 함께 고친다. 클래스 대신 `getByRole`, `getByLabel`로 옮겨 두면 이후 디자인 변경에 덜 깨진다.

### D3. 화면별 적용
순서대로 하나씩 바꾸고, 끝날 때마다 E2E 통과 → 기준선과 스크린샷 비교 → 커밋. 그 화면에서 쓰던 `style.css` 부분은 그때 지운다.
- [ ] 공통 상단바: 배치는 그대로. 흰 바탕 + 아래 `--line`, 검색칸은 `#F5F5F7` 알약, 버튼은 soft 알약, 로그아웃은 ghost.
- [ ] 로그인 / 비밀번호 변경: 가운데 흰 카드 하나 + 큰 제목 + 검정 알약 버튼.
- [ ] 배우 목록: 3장 와이어프레임. 큰 흰 카드 안에 회색 툴바 패널과 배우 카드. 상태는 `StatusDot`.
- [ ] 배우 상세 / 기록 탭: 왼쪽 프로필 흰 카드(사진 radius 20, 두 톤 요약 문장), 오른쪽 위에 `WidgetCard` 2~3개(수업일지 수, 최근 출석률, 계약 만료까지 남은 날), 아래 `SegmentedTabs` + 회색 패널 안 기록 목록.
- [ ] 배우 등록·수정 / 기록 폼: 흰 카드 2개(기본 정보, 파일). 파일 칸은 회색 패널 안 드롭 영역.
- [ ] 출결: 위에 `WidgetCard` 3개(출석, 지각·결석, 미체크 인원), 아래 흰 카드 안 `DataTable`. 저장 버튼은 "출결 저장 [n명]".
- [ ] 태블릿 출결: 무지 배경 + 흰 카드 + 숫자 4칸(회색 패널) + 키패드(soft 알약, 확인만 검정). 결과는 `WidgetCard`로 크게 보여 준다. `kiosk.css`를 CSS Module로 옮긴다.
- [ ] 계정 / 선생님 관리: 밀도 우선. 카드, 표, 버튼만 새 컴포넌트로 바꾸고 인라인 스타일을 없앤다.

### D4. 정리와 반응형
- [ ] `style.css`, `admin.css`, `kiosk.css`를 삭제한다. 인라인 스타일 0개를 확인한다 (`grep "style={{"`).
- [ ] 반응형 기준: 1240px 이상, 1024px(태블릿 가로, 키오스크), 768px, 390px(휴대폰).
- [ ] 휴대폰에서는 카드 radius와 padding을 줄이고(20 / 16px), 카드가 화면 폭을 채운다.
- [ ] **완료 조건**: 네 가지 폭에서 가로 스크롤이 생기지 않는다 (표는 카드 안에서만 가로 스크롤).

### D5. 검증

- [ ] D0 기준선과 새 스크린샷을 화면별로 나란히 비교해서 빠진 기능이 없는지 확인한다.
- [ ] 대비 검사: 본문과 보조 텍스트 4.5:1 이상. `#F5F5F7` 위의 `--ink-2`도 확인한다.
- [ ] 키보드만으로 로그인 → 배우 검색 → 상세 → 기록 추가가 가능하다.

## 7. 작업 규칙

- 기능과 API는 바꾸지 않는다. 디자인 작업 중 발견한 기능 문제는 `docs/found-issues.md`에 적는다.
- 새 라이브러리는 Pretendard 하나만 추가한다. 다른 것이 필요하면 이유를 보고하고 확인받는다.
- 색, 간격, 라운드 값을 직접 쓰지 않고 토큰 변수만 쓴다.
- 한 화면을 끝낼 때마다 E2E 통과 → 스크린샷 확인 → 커밋 순서로 진행한다.
